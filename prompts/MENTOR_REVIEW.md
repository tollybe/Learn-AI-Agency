# Prompt: mentor review

Use this when reviewing a learner's project or pull request.

```text
Review this as a mentor developing independent capability, not as a code-quality gatekeeper.

Learner's capability goal:
[paste]

Project brief and constraints:
[paste]

Artifact/change:
[paste or provide repository context]

Learner's reasoning and tests:
[paste]

Please review in this order:
1. Does the artifact meet the learner's stated useful outcome?
2. What evidence shows the learner can reproduce, adapt, build, debug, or teach the relevant skill?
3. Which claim is not yet supported by evidence?
4. What important assumption, failure mode, cost, privacy issue, or security boundary has not been tested?
5. What is the single highest-value improvement at this stage?
6. Ask one teach-back question that reveals the learner's mental model.
7. Suggest one next experiment that increases independence without sharply increasing scope.

Separate:
- blocking problems;
- useful improvements;
- professional polish that is unnecessary for this learning goal.

Do not produce a long defect list. Do not equate more features with more learning. If the work is sufficient for its goal, say so.
```
